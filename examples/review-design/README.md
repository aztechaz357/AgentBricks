# 見本: 設計書のレビューのスキル

`/new-skill` で作ったスキルの見本。材料はすべて架空で、試しのために作った。ここに置いてあるだけでは読み込まれない (有効なスキルではない)。

## 中身

| フォルダ | 中身 |
|---|---|
| `inbox/` | new-skill に渡した材料。いつもの進め方のメモ、レビュー前の設計書 (`input/`)、指摘を受けて直した後の設計書 (`output/`) が 2 組 |
| `skill/` | できたスキル。手順 (`SKILL.md`)、指摘の一覧の型 (`references/format.md`)、観点 10 個 (`references/checklist.md`)、例 (`references/examples/`) |
| `trial/` | できたスキルを、新しい設計書 (`03-shipping.md`) に使った結果 (`03-shipping-review.md`) |

## どう作ったか

1. 材料を `inbox/review-design/` に置き、`/new-skill review-design 設計書・仕様書のレビュー` と頼んだ。
2. new-skill は、前と後の設計書の違いを 1 つずつ挙げ、「なぜ直したか」を観点にした (例: 「速やかに」→「2 秒以内」から、観点「あいまいな言葉が数値や条件になっているか」)。
3. 指摘の一覧の実物はなかったので、メモに書いた表の列と重要度の付け方から型を作った。

## 試した結果

`trial/03-shipping.md` には、見つけてほしい抜けを 9 個仕込んだ。スキルは 9 個とも拾った (1 個は「観点の追加の候補」として)。

| 仕込んだ抜け | 拾った指摘 |
|---|---|
| 「必要に応じて」 | No 1 |
| 入力の形式と範囲がない | No 3、4 |
| 在庫が足りないときの動きがない | No 5 |
| 在庫と履歴を 1 つのトランザクションにしていない | No 6 |
| 権限の前提がない | No 10 |
| 「担当者」があいまい | No 10 |
| 要求番号 (REQ) がない | No 11 |
| 章番号の抜け | No 13 |
| 同時に登録したときの排他 | 観点の追加の候補 |

試したあと、使って分かった次の点をスキルに直した。`trial/` の結果は直す前のもの。

- 用語集のパスの基準と、用語集がないときの扱い
- 出力のファイル名 (拡張子を除く)
- 指摘に当てた観点の番号を書く。観点外の指摘の扱い
- 型に「当てた観点」の欄を足す

## 自分のリポジトリで使うには

`skill/` を `.github/skills/review-design/` に写し、`python tools/sync.py` を実行する。観点は架空の設計書から作ったものなので、自分のレビューの前と後の資料で作り直すほうがよい。
